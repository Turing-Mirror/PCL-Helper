# v4：旧版还原与连续更新验证

日期：2026-10-25。

## 已复现的问题

使用已发布 v2 修补官方 PCL 2.99.0.0，再用已发布 v3 还原，原文件 SHA256 可精确恢复。随后在原路径替换为官方 2.99.0.1，保留旧备份和记录，再用 v3 恢复下载，稳定报错：

> 已有不同原文件的备份，请先还原或选择新的 PCL 文件

原因是备份路径固定，而旧备份在还原后继续保留。新原文件与旧备份的哈希自然不同，原有检查把正常更新也视为冲突。此前只验证独立文件及补丁升级，遗漏了完整的连续更新链。

另外，更新后的未修补原文件仍带旧记录时，旧还原逻辑会报“被其他程序修改”，而不是识别当前文件没有 Helper 标记。

## 修复

- 在当前原文件通过版本和补丁结构检查后，将已有记录和不同原文件的旧备份复制到 `<EXE>.pcl-helper.history/`；历史文件按自身 SHA256 命名，再为当前文件建立活动备份。
- 已有相同原文件备份继续复用；重复操作保留原有行为。
- 还原前检查 Helper 标记。未修补文件返回无需还原，不覆盖当前文件或旧备份。
- 已修补文件仍必须通过备份与当前文件的 SHA256 校验后才能还原，不放宽外部修改检查。
- 下载、整合包和 HMCL 启动补丁逻辑沿用 v3，软件修补修订号仍为 3。

## 实测

直接运行本地保留的已发布 v1、v2、v3 EXE 生成旧补丁，再使用最终交付的 `release/v4/PCL-Helper-v4.exe` 执行操作，而非只调用重新编译的测试替身。

| 场景 | 结果 |
| --- | --- |
| v1 / v2 / v3 / v4 修补 2.99.0.0，再由 v4 还原 | 均与官方原文件 SHA256 完全相同 |
| 还原后的 2.99.0.0 在原路径更新成 2.99.0.1，保留旧备份 | v4 可修补、重复修补及精确还原为 2.99.0.1 |
| 更新后先点还原，再点恢复下载 | 未修补新文件不被旧备份覆盖，随后可正常修补 |
| 历史备份与记录 | 已核对原字节和 SHA256 均保留 |
| 同路径从 2.99.0.1 降回 2.99.0.0 | 可修补，并精确还原为 2.99.0.0 |
| 未修补原文件没有备份时点还原 | 成功返回无需还原，不创建或修改备份 |
| 已修补文件被外部修改后点还原 | 明确失败，当前文件保持原样 |
| 新旧两个 PCL 版本的基础回归 | 修补、检测、重复操作、SHA256 还原、实际 CLR JIT 与真实 WPF 下载页构造通过 |
| 真实 Helper GUI 操作旧版 2.99.0.0 | 自动查找、选择、批量修补与还原、单项失败继续、状态恢复通过 |
| 真实 Helper GUI 操作新版 2.99.0.1 | 同样通过，并验证下载导航及隐藏设置 |
| PCL 原图标 | 两个版本的 16 项原生图标、版本和清单资源均逐字节保持一致；系统实际提取出的 PCL 图标一致 |

图标尺寸完整保留：16、20、24、32、40、48、64、96、128、256 像素。新增 `tests/verify-icons.py` 使用 pefile 静态比较原生资源，不执行被检查的程序。

官方原文件 SHA256：

- 2.99.0.0：`6b6e1260cb5a1d6a303855f1c60cab3d0bc1aebba7e40a964180188b271e7386`
- 2.99.0.1：`0db34e19d9eeb6d496d20fabe786ec16bbd36ba6b0ccdc8d29cb7e909c114397`

连续更新测试使用官方新版原文件替换同路径 EXE，复现更新后保留旧侧边文件的状态；未执行 PCL 自动更新服务器下载与重启。本次没有重新跑全部游戏下载，v3 的安装验证结果见 [历史报告](../v3/pcl-support.md)。缺失原始备份或记录的已修补文件仍无法保证精确还原。

## 复现

```powershell
.\tests\compatibility.ps1 -OldPclPath 'PCL 2.99.0.0 原版.exe' -NewPclPath 'PCL 2.99.0.1 原版.exe' -HelperPath 'release\v4\PCL-Helper-v4.exe' -LegacyHelpers @('v1.exe','v2.exe','v3.exe')
```

每次使用独立输出目录。所有原始程序、补丁副本、备份、完整日志及构建结果保存在被忽略的本地目录，用户现有启动器未被测试修改。
